# County borrowing identities and source observations

County borrowing uses a dedicated instrument identity (county, issuer namespace, explicit reference) and dated source observations. `Loan` remains the national creditor bucket and legacy county/pending bills representation with its existing uniqueness; `DebtInstrument` remains the Treasury redemption register, whose face values are not outstanding stock. Lender/date cannot distinguish contracts, and relaxing Loan uniqueness would undermine aggregate upserts.

An observation is keyed by instrument, stock date and source document. Exact replays are idempotent; changed same-key facts require explicit correction, updating that account and incrementing its revision. Different sources remain competing accounts. Each instrument contributes only its latest recorded date, including missing/withheld observations, so an older balance cannot reappear. Addition requires compatible dates, currency, entity and actual basis. Multiple accounts for the same instrument on that date withhold the total. Different dates are never added as instruments.

Identity comes from explicit writer arguments, not arbitrary metadata prose. There is no migration or automatic backfill of legacy JSON identities. Mixed legacy borrowing and explicit instruments withhold the total pending reconciliation because their overlap is unknown; pending bills keep their existing separate reader. Coverage means selected eligible instruments only, never all county liabilities. NULL money stays missing and measured zero stays zero. Corrections do not provide a historical version ledger; distinct dated/source observations remain stored.

The migration creates only the two tables and their constraints/indexes. Downgrade refuses populated tables to avoid silent evidence loss. Production adoption, source identity reconciliation and any historical backfill require separate acceptance.

Release compatibility: the reader performs one PostgreSQL catalog lookup per adapter call before querying either new table. When both tables are absent, it continues to read the established sourced `Loan`/pending-bills accounts. When both exist, it reads explicit instruments as well. A partial schema and actual catalog/data query errors remain failures; they never become an empty instrument cohort or zero debt. Schema absence is not cached, so subsequent calls observe an authorized adoption without restarting the process. The existing selected-evidence coverage contract remains in force. This permits merging the representation before an authorized production migration; it does not claim source ingestion or a production data repair.

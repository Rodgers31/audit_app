## Selection and cadence

`seed.yml` forwards three repository variables, each defaulting to the literal `false`: `SEED_CRA_INGESTION_ENABLED`, `SEED_OPENDATA_INGESTION_ENABLED`, `SEED_KNBS_RELEASE_DISCOVERY_ENABLED`. Values must be literal `true` or `false`. Discovery also requires the OpenData flag. Registration/handlers keep existing individual opt-ins; passing a flag does not authorize activation.

`python -m seeding.source_plan --check` validates whitelist, booleans, supported trigger/cadence before migration. `--execute` builds an argument vector for the unchanged native `seeding.cli`, with explicit `--domain` arguments and dry-run state. Inputs never enter executable shell. Manual empty selection retains fifteen legacy domains plus explicit opt-ins. Enabled opt-ins run first in both manual default and Sunday plans, before the unchanged legacy order; the fixed native1320-second default budget still records and fails any budget drop. This priority does not certify complete17-domain capacity. Selected manual domain uses only that native handler, but shared migration/health/validation remain broad: **this workflow is not a no-write preflight**. Native preview still writes operational jobs/receipts. The separate preflight lane owns no-write readiness.

Daily Monday–Saturday02UTC selects fifteen legacy domains; Sunday03UTC selects them once, plus optional CRA/OpenData, and bootstrap follows successful seed and migration. This removes Sunday's duplicate all-domain run while retaining seed-before-bootstrap order and existing bootstrap validation/refusal. The validated plan job exports only whitelisted domains and planned bootstrap; the summary reports those separately from seed/bootstrap job outcomes and labels refused or missing plans unverified. Empty requested domain is shown as all (default plan). No static calendar frequency is silently reinterpreted as executed cadence.

## Discovery budgets and source gates

The optional OpenData observation uses only `https://www.knbs.or.ke/reports/`, its latest linked `20xx-economic-survey/` report and one `Chapter-5-Public-Finance[-suffix].xlsx` link. Maximum two HTML pages, sixteen eligible links per page, 2,048 anchors, 256KiB per HTML response, 1MiB workbook, 2MiB cumulative body bytes, six attempts total, at most one retry per GET with0.5s backoff, ten-second HTTP operation timeout and enforceable45-second whole-call wall clock. Redirect budget0, exact `www.knbs.or.ke` HTTPS host, no port/userinfo/query/fragment, ambient proxy/credentials disabled, identity content encoding only. No upward-configurable budget. Unsupported/non-main-thread hard-deadline contexts refuse before network. A preexisting shorter native alarm remains bounded and is restored with elapsed time deducted.

Conditional ETag/Last-Modified is limited to bounded observed HTML link receipts from terminal native jobs. An unsolicited304, malformed validator/state or unknown version refuses. Workbook bytes are always checked: a304 listing never hides changed bytes behind an unchanged URL. Same bytes/accepted URL replay uses existing append/idempotency proof and retains original source/extraction timestamps. A different URL with identical bytes is recorded as an alias candidate, not a new accepted edition. Source identity/version, last checked and candidate reason survive as native job metadata; no raw document is newly cached/uploaded.

The pinned parser remains the only accepted semantic contract: exact checksum before ZIP/XML, table/sheet, ordered47 counties +Total, 46period/metric columns, units from its reviewed evidence, raw provisional/revised/unspecified labels, missing blank/dash distinct from numeric zero, original arithmetic discrepancies. No automatic financial promotion. Unknown bytes, future editions, PDFs/layouts/units/geographies/labels/revisions do not reach this parser or writer. They yield a bounded quarantined candidate with unknown periods/publication date and explicit review reason. Even an apparently compatible new edition needs authentic edition-specific unit/reference/revision evidence; **this PR does not claim future compatible-edition ingestion completeness**. A later reviewed contract can extend admission without altering the pinned checksum. Additional datasets/UI remain #745.

## Durability, failures and rollback

The native CLI/dedicated worker keeps existing idempotency keys, exact running observation, nonce-bearing domain lock, claim exclusion, terminal acknowledgement and retained uncertainty. Ownership is checked before discovery and again afterward; pinned persistence rechecks it on the write transaction. Discovery metadata commits with the native terminal job. Partial parser/writer failure rolls back source/extraction effects. A killed owner retains its claim; no age/force-release path is added. Cancellation, pending/duplicate commands and stale jobs use the existing shared infrastructure, exercised in the affected cohorts.

A quarantined candidate has zero facts/extractions and a native `COMPLETED_WITH_ERRORS` job, refused freshness and a specific reason. The existing native CLI can exit0 for `COMPLETED_WITH_ERRORS`; do not read exit0 as source acceptance. The real workflow hollow-run gate rejects this refused mode, and the dedicated command terminal is failed. Transport/budget/invalid source failures remain failed jobs. Source history is labelled recorded-only, never a current public verification.

Rollback is to leave all opt-ins false and revert the scoped source/workflow commit. No schema reversal or data rewrite is needed. Existing accepted rows and retained claims must not be cleared. Local evidence is not an intended-host operator run or a provider capacity/Free viability proof. Request/byte ceilings are operating limits, not a measured savings claim or a promise that provider usage is free.

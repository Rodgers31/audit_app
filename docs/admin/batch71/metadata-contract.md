# Metadata preflight protocol 2 (#785)

This is a separately reviewed metadata workload, **not write admission**. Both
version 1 and the checked-in version 2 admission remain disabled. Nothing in this
change installs a database function, grants access, starts a worker or enables
Actions, publishing, uploads, generation or social processing.

## Why a separate protocol is needed

All six production relations use RLS. Ordinary filtered reads cannot prove that
claims/jobs are absent. Existing restricted logins lack both full statistics
visibility and the six-table SELECT set. PUBLIC grants TEMP; a per-login REVOKE
cannot remove it. Version 1 deliberately refuses these conditions and retains
its existing direct-TLS, startup guards, no-TEMP credential and 24-command limit.

Measured on the existing Render host: direct database TCP was unavailable. The
existing session endpoint is reachable with verify-full client TLS and the
existing independently provisioned CA file; it ignores libpq startup settings.
`pg_stat_ssl` describes the pooler-to-database leg and reports false even though
libpq verifies client-to-pooler TLS. No paid IPv4 option is requested.

Version 2 therefore admits only an explicitly approved **clean client session**
workload on the pinned session endpoint (port 5432). Transaction pooling (6543)
is refused. It does not claim a new physical backend or end-to-end database TLS.
It pins the backend PID across two transactions, checks that no temporary schema
exists before/after, and admits the independently pinned inherited TEMP boolean.
The login retains that capability outside this invocation. No temporary table
creation or temporary/persistent DML is in the tool's SQL allowlist.

## Privileged interface proposed for explicit owner approval

The exact installer is generated by
`scripts/verification/ingestion_metadata_contract.py:installation_sql` with the
fixed reader `audit_app_audit_reader`. It is an operator action, not a migration.
It creates the previously absent `audit_preflight_v2` schema and one zero-argument
`observe()` SQL STABLE SECURITY DEFINER function, owned by the existing postgres
owner. It grants only schema USAGE and function EXECUTE to the existing reader.
It grants no role membership, application SELECT, write permission or BYPASSRLS,
creates no login/credential, and changes no RLS or PUBLIC database privilege.

The function returns exactly: protocol 2, one capped Alembic revision, the seven
existing claim/dispatch/worker/job/activity/prepared-transaction booleans, and a
boolean confirming complete activity visibility. No application row, ID, query
text, token or parameter is returned. Unknown/null nonterminal state refuses.
The existing owner supplies RLS/statistics visibility inside the fixed function;
the caller remains unable to SELECT the underlying data or full statistics.

Installation refuses an existing namespace, direct privileged role flags,
delegated reader access, memberships held by the reader, and effective database
CREATE, application writes/ownership, sequence usage/update or schema CREATE.
All creation/revocation/grants occur in one transaction with 2s statement and
500ms lock bounds. Failure rolls the transaction back. Never use CREATE OR
REPLACE to absorb unknown existing state. Rollback of an accepted installation
requires a separately reviewed access-removal action; this tool performs none.

## Binding and execution

An operator must prepare the admission independently of the inspector: exact
accepted source HEAD and all thirteen file hashes, provider endpoint/qualified
login/database/role OIDs, independently provisioned CA path and bytes, six-table
schema hash/revision (including the public namespace and each relation OID),
fixed function namespace/function/owner OIDs and body
hash, and separately accepted receipt/custody identity. The inspector does not
learn expectations from its target. Receipt identity is bound, **not verified**;
the report always leaves custody UNMET and receipt backend NOT_OBSERVED.

Source kind is explicit: `git-checkout` requires real Git HEAD; `reviewed-bundle`
requires an independently hash-pinned `PREFLIGHT_SOURCE.json` with exactly version
1, the reviewed execution HEAD and the thirteen source hashes. Every actual file
must match both manifest and admission. There is no automatic fallback between
these kinds. The API launches the fixed worker path inside the admitted root;
the parent also verifies its own thirteen source files against admission before
launch, since it independently replays the child's records. A bundle records
reviewed source provenance, not a Git checkout on
the host. The operator must extract those exact paths from the accepted Git
commit, independently verify the archive/manifest, copy only that reviewed tool
bundle to a private temporary directory, and remove it after qualification. No
database record or credential belongs in the bundle. This avoids adding Git to
the minimal Render image. The mounted CA's canonical non-symlink target and hash
must be independently pinned for the current instance; do not relax file-link
checks to follow an unknown target.

The supported API and CLI share one nonconcurrent 30s parent deadline and a
fresh isolated interpreter/process group, one connection, 3s connection timeout,
2s statements, 500ms lock timeout, 3s idle transaction and 5s idle session limit,
64 KiB work memory, no query parallelism/retries. The existing host driver is
psycopg2 2.9.13; this protocol pins that exact version separately from v1's
2.9.12. Each transaction begins READ
ONLY before any application SQL and sets/verifies all local guards explicitly.
An existing/unknown libpq transaction state refuses before BEGIN; explicit wire
ROLLBACK and an IDLE readback are required between snapshots and at cleanup.

The first transaction verifies role/schema/function metadata before invoking
the privileged function. A second fresh repeatable-read transaction checks
persistent schema/function/session drift. The bound is 29 SQL commands, nine
reads, 256 total rows, 65,536 decoded bytes and two rollbacks. Both child and
parent replay every bounded metadata/observation record; only the sanitized
summary crosses into the public receipt. Forced termination, missing records,
unknown data, cleanup uncertainty or any drift refuses. The parent confirms its
owned process group is gone. Credentials travel only through private stdin;
driver errors, credentials and connection URLs are never serialized.

Linux uses the explicit `linux-proc` census backend: at most 16,384 `/proc`
entries, at most 4,096 bytes per PID stat, the same whole-run deadline, and only
PID/PGID results. Process names, arguments and environment are not returned.
The held unreaped leader prevents group-ID reuse during cleanup; group absence
is verified after reaping. Other supported local systems use the existing `ps`
backend. This choice is in the receipt; v1 retains its original default backend.
The actual Render image needs no additional process-list package.

The result is a point-in-time observation. It cannot exclude a later writer,
prove malicious-owner exclusion, establish backup custody, certify provider
costs/free-tier suitability, or authorize a job. Those remain separate gates.

Example, only after a reviewed independently prepared admission exists:

```sh
python -B scripts/verification/ingestion_metadata_preflight.py \
  --reviewed-admission /absolute/private/admission.json \
  --expected-admission-sha256 REVIEWED_SHA256 --execute-read-only \
  --out /absolute/private/fresh-receipt.json
```

Supply the existing connection URL only as the process-local
`INGESTION_PREFLIGHT_DATABASE_URL`; never put it in CLI arguments or a receipt.
URLs with query options, alternate hosts/users, fragments or service/cert-path
overrides are refused. A reviewed operator wrapper may construct a bare URL from
the existing service secret in memory; the trusted CA comes from admission.

## Owned qualification

Tests require an explicit cached PG17 fixture on 127.0.0.1:56972. The version 2
database is `b66_preflight_metadata`, with a distinct local-only role and default
PUBLIC TEMP retained. Six RLS-hidden tables and a private sentinel are created
only there. No production data or credential is needed. The integration fixture
fails instead of skipping if it is absent. Run the old and new suites in separate
pytest invocations because the historical suite exports its own `conftest` API.

After read-only qualification, source/worker/custody/resource gates must still
pass before the separately authorized single bounded admin dry run. Do not turn
on Run Now, scheduled workflows or production publishing to obtain acceptance.

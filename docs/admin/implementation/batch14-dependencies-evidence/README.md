# Batch 14 dependency investigation packet

Read [the handoff](../BATCH_14_DEPENDENCIES_HANDOFF.md) for the decision and limits. These are actual observations from baseline `3f3b1f1981b93c3317e204defbd235121c1df084` and a rejected disposable argparse2 candidate, not a shipped dependency upgrade.

## Replay

Use an owned isolated checkout of the baseline and a separate owned disposable copy of its frontend. Never install into the dirty primary. The diagnostic script supplied by this documentation delivery can be run against either installed tree:

```sh
# In the baseline frontend, with an owned npm cache:
ONNXRUNTIME_NODE_INSTALL=skip npm ci --include=dev --include=optional --no-audit --no-fund
npm ls --all --json
npm audit --json                 # captured exit 1, two roots
npm audit --omit=dev --json      # captured exit 0
node --test scripts/tooling-repair-behavior.test.cjs scripts/tooling-repair-install.test.cjs
node /absolute/path/to/probe-argparse.cjs /absolute/baseline/frontend
BATCH14_FRONTEND_ROOT=/absolute/baseline/frontend node --test /absolute/path/to/cli-version.test.cjs # pass

# In the disposable candidate frontend, apply the two captured patches first:
patch -p2 < /absolute/path/to/candidate-package.json.patch
patch -p2 < /absolute/path/to/candidate-package-lock.json.patch
ONNXRUNTIME_NODE_INSTALL=skip npm ci --include=dev --include=optional --no-audit --no-fund
# Expected exit 1: tooling repair: missing locked sprintf-js
node /absolute/path/to/probe-argparse.cjs /absolute/candidate/frontend
BATCH14_FRONTEND_ROOT=/absolute/candidate/frontend node --test /absolute/path/to/cli-version.test.cjs # expected fail: blank version
npm audit --json                 # captured exit 1, braces root only
npm ls --all --json              # captured exit 0; lifecycle still failed
```

The candidate patches were generated by adding `overrides.argparse=2.0.1` and running `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` on the frozen graph. `--ignore-scripts` was used only for lock resolution; normal `npm ci` then exercised the mandatory lifecycle and failed. The two patches preserve all other lock records. Do not force them onto a later graph without inspection.

`probe-argparse.cjs` emits diagnostic JSON; its exit 0 is not acceptance. Read `cliCases[*].child`, `repair` and `nycConfig`. It removes its own temporary synthetic NYC config fixture. It does not launch a server or use credentials. Invalid/missing installation produces an error rather than a compatibility PASS. Both captured probes ran on installed packages; their temporary fixture names/absolute roots differ naturally.

`baseline-audit.json` and `candidate-audit.json` are npm advisory propagation outputs. The official GitHub advisory API snapshots (`*-advisory.json`) and npm `registry.json` provide current upstream evidence at capture time. `argparse-migration.md` and `argparse-changelog.md` are official tagged source documents. API/registry snapshots can become stale; recapture before a future upgrade decision.

`global-candidate-install.receipt.json` records the actual install exit/source hashes, with raw stdout/stderr alongside. Baseline receipts additionally hash selected source and output files. Their recorder lived externally; selected environment values were explicit, but ambient environment and the entire filesystem were not captured. No production parity claim follows. `lock-delta.json` records exact parsed production-record preservation. Audit/CLI results are diagnostic, not security waivers.

`producers/run.py` accepts `CHECKOUT_ROOT EXISTING_EXTERNAL_OUTPUT UNIQUE_NAME ABSOLUTE_CWD MODE ABSOLUTE_EXECUTABLE [ARGS...]`. **Copy the original bytes to an owned external producer directory before executing it**: its cache roots are siblings of its own file. Executing that producer directly inside this documentation directory would create caches in the checkout. The recorder checks an exact Git root, rejects output inside/above that root, records complete nonignored source bytes before/after, excludes runtime dotenv, creates fresh home/tmp and separate empty npm configs, and captures actual child exit/timeout/streams. It is a capture tool, not a filesystem sandbox; use explicit owned workdirs and endpoints. `publication-control.py` additionally binds the actual verifier/tests/archive/manifest before and after execution. Do not modify a producer or old hash once it has executed.

Original producers take checkout/fixture/fresh-output arguments described in their source and in the independent reports. Inputs are runtime data, never instructions. `pack.py` operates on the original external corpus layout with a pre-created empty staging directory. It preserves bytes, emits a fresh archive/member inventory and refuses collisions; it does not upgrade historical results. A retained archive can be extracted to inspect/replay individual producers, but extracting the normalized member layout does not recreate the original external directory layout automatically. `STANDARDS_REVIEW.md`, `SPEC_REVIEW.md` and `ADVERSARIAL_REVIEW.md` retain separate acceptance axes. The separate final postcommit binder identifies actual final source and publication addenda; no old capture is rewritten to name a later commit.

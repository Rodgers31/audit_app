## Actual protocol

1. Authenticated `POST /api/v1/admin/social/connections/meta/direct/start` requires a verified admin/Supabase session UUID, exact configured frontend origin, reason, idempotency key, and qualified exact API callback. It creates a ten-minute attempt using existing `SocialOAuthFlow`. The response contains a flow UUID and a random launch nonce in its body, never code/state or a provider authorization URL. Durable command receipts omit the nonce.
2. The Accounts component submits that nonce and flow UUID by a transient top-level form POST to `/api/v1/social/oauth/meta/launch` on the direct API origin. The route checks the actual target and Origin, consumes the nonce under row lock, sets a per-attempt `__Host-` Secure/HttpOnly/host-only/SameSite=Lax cookie, and returns a 303 to the fixed official Facebook code dialog. No bearer token is placed in a form or URL. The state is confined to the necessary provider redirect leg.
3. The provider returns to `/api/v1/social/oauth/meta/callback` on that same API origin. The route checks exact target, bounded unambiguous query, state hash, browser cookie, expiry, privacy block and original per-attempt origin. It stages code or denial encrypted under the existing `oauth_start` envelope purpose, destroying the state/launch/browser material. It performs no provider request. No token is accepted as callback input.
4. Standalone no-store/no-referrer/script-hashed HTML removes the query. Its only opener message is `{type: 'auditgava-meta-ready', flow_id}` targeted to the exact frontend origin. The opener requires the expected origin, popup object and active flow UUID and rejects extra keys, including code/state/token keys. The flow UUID cannot authorize any operation by itself.
5. Authenticated `POST /connections/meta/direct/complete` uses the original actor and Supabase session binding, validates the exact staged envelope and current redirect, and commits one-use consumption before provider I/O. A separate in-memory claim plus persisted flow validation protects the shared exchange seam from unclaimed service calls. Concurrent/replayed requests cannot repeat the effect. Provider uncertainty leaves a failed/exchanging attempt requiring new authorization, rather than resending the code.
6. Discovery and explicit Page/Instagram selection use the existing privacy ownership/provider inspection, account identity and concurrency controls. New accounts keep publishing disabled. Lost completion can recover choices without code replay; a staged callback can be explicitly completed by its original authenticated session.

The outer private middleware preserves the route's CSP after the global security middleware. Failed exact callback GETs, including early rate-limit responses, preserve the error status and serve only query-scrubbing HTML without a ready hint. Launch failures return generic private errors with no reflected input. The legacy Vercel callback and its middleware bypass remain present under the original admission hold.

The launch nonce is sensitive despite limited authority: before use it can bind one browser to an existing attempt, but cannot read a grant, exchange a code, choose accounts or publish. It is one-use, expires with the attempt, requires exact Origin, is absent from durable receipts and URLs, and is destroyed on launch. Loss can disrupt that attempt and remains part of body/cookie collector qualification. The flow UUID is an identifier/hint; every privileged operation independently checks actor/session, expiry/privacy and lifecycle.

## Threat model and caller coverage

Untrusted callers may forge callback queries/messages, supply encoded or duplicate keys, race callback/complete/launch requests, replay receipts, change host/origin/session, and inject malformed decrypted envelopes through a corrupt fixture. Bounds reject empty, unknown, malformed UTF-8/percent sequences, decoded duplicate names, simultaneous code/error, token fields, controls and oversized payloads. Configuration rejects noncanonical default ports and numeric-host aliases that browsers normalize. Origin changes invalidate existing attempts. No provider-supplied URL controls an outgoing endpoint.

All new ingress uses `DirectCallback`; direct start/complete and shared provider entry points repeat admission before DB/provider work. Legacy start/complete cannot accept the direct URI or bypass invalid direct mode. The shared `exchange_claimed` path validates a one-use internal claim and the persisted actor/session/status/redirect before provider construction. Existing `select`, discovery, ownership/privacy blocking, expiry purge, recovery inventory and envelope rotation retain their persisted model/purpose contracts. Purge clears the reused verifier field; generic envelope inventory/rotation retain it without depending on a legacy `{'state'}` payload shape. No generation/ingestion ownership changed.

Residual trust boundaries include frontend XSS, compromised admin sessions or application keys, provider/host correctness, actual cross-origin browser delivery and all external collectors. This implementation cannot protect a secret from a hosting collector that observes the original query/body/cookie. Do not accept it on a missing dashboard result.

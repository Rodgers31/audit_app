# AuditGava redesign implementation plan

Phase 0 · Owner approval pending · Planned against `origin/main` at `80aeb2c`.

Open [the design spec](index.html) in a browser. All seven tabs, the [spec index](SPEC_INDEX.md), and GitHub issues #922–#943 were reviewed. The written spec and after-mockups govern, followed by the linked issue, the [parent prompt](CODEX_PARENT_PROMPT.md), and repository conventions. When two specs or an API contract disagree, bring the affected decision to the parent before changing that part.

## Working boundaries

- Use independent worktrees and branch from the current `origin/main` after the prerequisite PRs merge. The parent owns shared files and coordinates any change needed by multiple workstreams. All other workstream paths are read-only, including shared test fixtures unless assigned below. New files and test files follow the same ownership as their feature.
- The plan PR contains this document. Phase 1, implementation branches, sub-sessions, and merge activity wait for owner approval.
- Seeding and refresh repair can proceed independently of the plan and most frontend branches. Keep the nightly workflows, release configuration, source registry, revalidation paths, and production database outside the redesign worktrees' routine changes. Recheck current PRs, branch file lists, and API contracts before starting W1, W11, W15, schema work, and before moving `main` during a refresh verification window. Coordinate with the refresh owner where a change affects the working revision or an accepted-document contract. Verify with fixtures or a disposable database. W15 requests a handoff for any overlapping publisher/date writes. Keep the OAG extractor and nightly health checks with the refresh lane; W8 uses a reviewed amount contract layered over published findings.
- Read-only cross-team interfaces include the county and fiscal APIs, React Query cache keys, audit publication rules, and the existing sign-in and watchlist behavior. Preserve public links, URL parameters, provenance, published/withheld distinctions, and SSR first paint. Avoid publishing operational incident details or credentials.
- Apply `#f-signs`, `#c-rules`, and the signal and typography rules within each owner's files. Use API values and coverage, including for titles, calculated takeaways, charts, images, and quiz answers. Keep unavailable values explicit and preserve qualified data. Use the approved brand and one opaque dark title band. Keep the five social logos and their links exactly as implemented.

## Decisions and dependencies for the owner

- **Audit score basis (#923/#924).** Proposed course is to keep the multiyear published total for the Audit/Score comparison, expose both periods, and base score deductions on a matched audit-and-budget period when source coverage permits. If there is no comparable period, withhold that ratio from scoring with a reason. Confirm this treatment and whether to preserve the existing grade bands with the resolution factor marked “Not applied”. The C7 mockup contains the stale Open deduction; its visual structure is in scope and the plotted operands must come from the corrected API. The chart audit's “qualified/adverse” estimate also conflicts with E10's reserved opinion labels; use E10's real-opinion rule.
- **Replacement chart tests (#929).** The issue asks to tap a donut and a treemap, and the approved chart/route specs replace both. Verify tap, keyboard, clear and table data on the Budget segmented bar and Debt ranked lenders as their replacements. Confirm this acceptance mapping.
- **Mobile search (`#e2`, `#i-onestop`).** The mobile header after-mockup has one right-side Menu control and the discovery section calls for a search icon. Proposed placement is within the drawer, with search also on Home and 404, pending approval of the header placement.
- **Sourced inputs.** Verify county commitments, age bands, wage/revenue basis, latest publisher documents, reports-read counts by year and paired values for evidence disagreements. Check the APIs for any requested fields before placing them in the UI. Raise specific missing fields or incompatible periods. Use the [Public Finance Management Act](https://new.kenyalaw.org/akn/ke/act/2012/18/eng%402023-11-02/source.pdf) and [County Governments Regulations](https://new.kenyalaw.org/akn/ke/act/ln/2015/35/eng%402022-12-31/source.pdf) to verify the development and wage rules and correct denominator/period wording before shipping the county meter.
- **Legal facts and counsel.** Supply controller identity and postal address, registration/exemption and nonprofit status, locations/processors and retention including backup duration, effective date/version, contact addresses, real email cadence, code and content licences, editorial code, response windows and any confirmed public claims. Counsel should review the Part 7 wording and its consent/age treatment, the unaccounted-funds explanation, corrections process and data-access timing. Any browser storage and email flows introduced by Learn, Explorer or Follow need to be reflected in the approved policy.
- **Mail and review inputs.** Identify the reviewer for amounts and source quotes, the reviewed Kiswahili legal/Constitution texts, and the acceptable source for deduplicated new county audit/budget notifications. Clarify the treatment of earlier accounts and subscribers with no verifiable consent. These inputs can land after plan approval and before their dependent release.

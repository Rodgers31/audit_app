# County audit list page citations — issue #359

Implementation commits: `92df632c152e3d0db61badecc7a5c258ce482af5` and follow-up `1c08d7b1bf72339d819987429619f38b7cb5b543` on `codex/county-audit-page-citations`, based on `a7faedb509b63e8ac68557bf90456cb6f2828629`.

## Change and contract

`backend/main.py::list_county_audits` now maps `Audit.page_ref` to `source.page` through `services.audit_citations.citation_page`: a positive numeric page (the first page of a range) is a number; a recognized named locator such as `Annex VII` is retained as text. Both database and enhanced API paths expose `source.page_url` through `report_page_url`. A valid numeric PDF page replaces any old `page` fragment while retaining other settings. The list endpoint opts into removing a stale `page` fragment for a named or invalid locator, retaining settings such as `zoom`. This opt-in leaves other `report_page_url` callers unchanged. Malformed, zero, and negative textual references yield `source.page: null`; absent references remain withheld by the database publication gate. An invalid URL yields `source.page_url: null`. `AuditListWithSources` renders a named locator without claiming a numeric PDF jump, checks the link's HTTP(S) protocol, and opens the document without constructing a page when talking to an older API that lacks `page_url`. The existing source title, fiscal period, and `publishable_audit_criterion()` query remain in place.

The additional response field is `items[].source.page_url: string | null`; `items[].source.page` is `number | string | null`. The frontend type marks `page_url` optional for an older API response. `AuditListWithSources` itself is not mounted on the current county page; that page uses the comprehensive API and `AuditTab`, verified below. No schema or stored record changed.

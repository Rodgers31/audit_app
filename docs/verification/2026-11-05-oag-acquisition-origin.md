# OAG acquisition origin and source fidelity

Audit PDF availability, retained bytes, HTTP acquisition origin and public content qualification are separate outcomes. A cache filename, sidecar, matching digest or object-store conditional PUT response cannot establish the original HTTP acquisition.

The audits handler passes its running ingestion context to `fetch_document`. Before transfer, and again before source metadata changes, the fetcher verifies the current Kenya/audit/publisher/source association and exact running job. After transfer the rows stay locked through receipt persistence. Invalid contexts and conflicting current source rows refuse before Layer-2 metadata changes, including FAILED-state bookkeeping after a failed transfer.

For a fetched edition, `ensure_audit_origin` first resolves an existing immutable original and reads back retained bytes. Missing, malformed or stale origins can recover only through an actual complete official HTTP200 acquisition capability, exact edition equality, PDF identity checks, configured retention/readback and immutable database receipt readback. Local bytes and serialized receipts never manufacture that capability. Recovery shares the remaining per-document transfer allowance and existing byte/storage caps. A separate current-job validation binds the original extraction/hash and preserves the original acquisition time. A stopped job, changed source/edition/destination/origin or failed provider read cannot reuse the proof.

Original and current-job receipts use `pdf-receipt-v1` with `unparsed-acquisition-v1`, explicitly classified as auxiliary metadata. They contain no financial observation and cannot satisfy a nonempty finding inventory, source-plan admission or native report/publication-day authority. `audit_acquisition_origin_v1` is per-document operational evidence; a later contextless fetch records a held diagnostic instead of carrying an earlier qualified status forward. A failed origin is reported separately from byte-retention telemetry; it is not automatically an object-store incident.

The national FY2024/25 PDF's paragraphs778 and2169 contain historical table rows with overlapping embedded glyphs. Version5 reads targeted two-column `No. / Audit Issue` tables by the PDF's own marked Table/TR/TD cell membership. Four source suffixes exist in embedded cells but fall outside their rendered clip rectangles. Their exact embedded text is retained with `layout_qualifications`, while visible publication fidelity stays held. The common replacement/reconciliation guard refuses any present layout-qualification field, even for additive-only candidates or an exact source-complete review; it still emits an unapproved proposal. The loader independently refuses that field before creating/revising facts. Existing public evidence and all historical items remain; extraction/load transaction guards still refuse a partial replacement. No source approval flag or native financial bypass is added.

Production source adoption, native availability scope/publication date, exact locked-runtime combined qualification and full ordinary nightly acceptance remain separate. This local change authorizes none of those operations. The external lane handoff records exact source/proposal identities, executed case inventories, failures, independent reviews and remaining gates.

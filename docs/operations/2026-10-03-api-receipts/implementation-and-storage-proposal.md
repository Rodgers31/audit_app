## Implemented boundary

`services/receipt_store.py` defines `ReceiptStore.put(bytes)->digest` and `read(digest)->bytes`; `LocalReceiptStore` is the concrete local adapter, SHA256 keys, bounded 64MiB objects, exclusive atomic links, file/directory fsync, no overwrite, and digest-checked readback. Existing corrupt objects refuse both put and read. `SeedingHttpClient` accepts an injected adapter; its default is explicitly local `settings.storage_path/response-receipts`. Production durability has not been selected or established.

`services/response_receipts.py` captures actual response.content bytes, original request method/URL including parameters, final URL, actual status/type/encoding, acquisition time, size, digest/key and actual byte_check. The digest scope is the decoded HTTP entity bytes that httpx exposes to the parser, not compressed wire framing. Cache acquisitions with no retained original download timestamp have acquired_at=NULL and transport unchecked. Receipt failures log at error level and emit missing bytes/reason; observed values can still progress with weaker evidence. Database persistence failures propagate to the domain transaction/savepoint.

One immutable metadata-only existing Extraction is reused per acquisition/document. Bytes never enter SQL. Source observations are created by the actual parser before the writer; the receipt manifest includes raw values, units, identity, actual locator and transformation. Persistence deep-copies the manifest; changing the incoming object after flush cannot alter it. Fact meta/provenance carries compact `source_evidence` references. API/page-less web receipts have NULL PDF page. The shared read evaluator is owned by the reader lane and still needs final integrated acceptance. Transformations use identity/multiply with integer rounding digits and explicit ROUND_HALF_EVEN or ROUND_HALF_UP, bound in the parser manifest.

## Concrete durable-storage options for owner decision

Repository configurations establish candidates, not a current operational ownership/price inventory:

1. **Existing Supabase project storage**, if the owner confirms available capacity and storage access on the DB/auth project referenced in `.env.example` and `backend/.env.example`. Implement the Protocol against a private immutable bucket with restricted service writes, read-only audit access, and signed on-demand source access. Never put raw payloads into PostgreSQL rows. Require no-overwrite operations and a GET readback SHA256 after write, lifecycle/versioning/backup contract, and a separately owned recovery copy. Project storage quota, egress, current rate and region are unknown here; root must obtain the account's actual plan/quote before approval.
2. **Owned persistent filesystem/disk**, if the actual host/container lifecycle is confirmed. `docker-compose.prod.yml` already defines `etl_downloads:/app/downloads`; this is a configured candidate, not proof the deployed backend has a persistent receipt mount. A dedicated receipt directory on the approved persistent volume can use the implemented local adapter. Require restricted writer permissions, read-only backend mount, snapshots plus an off-host copy, restart/restore drill and quota monitoring. No extra provider service is provisioned here. Incremental disk capacity, snapshot, backup and outbound bandwidth costs remain subject to the owner's actual host contract.
3. **An already owned private object-store account**, only after root verifies such an account exists; no such configured bucket was found in the inspected source. It is an optional candidate rather than a claim of ownership. Same immutable-key/readback/access/recovery requirements apply.

Do not choose a provider merely because a free allowance might exist. No SDK/service/token/provisioning is added for an unapproved provider. The Protocol and constructor injection allow the approved adapter to be supplied later.

Retain referenced objects for the lifetime of the cited published observation, including superseded versions and archive dispositions. Local implementation has **no automatic deletion**. Approve an explicit orphan grace period (suggested30days), referenced-object inventory and backup reconciliation before any GC. Keep receipt metadata readable if bytes are lost, mark the byte check missing/mismatch on revalidation, preserve legitimate qualified observations and restore only digest-matching bytes. Same-URL replacement must create a new digest; it cannot repair an old version.

Costs can be reviewed without inventing a current provider price. Measured example:5 local objects from GDP, CBK and KRA/page/shell occupy768969 bytes. A conservative planning scenario of100 changed100KB API/web responses per day adds3.65GB/year;100 changed10MB PDFs per month adds12GB/year. Identical content adds0 body bytes in CAS; each actual acquisition still has metadata. These are scenarios, not forecast production volumes. Storage cost = retained GiB × account storage rate; read/restore cost = outbound GiB × account egress rate plus request/snapshot/backup charges. Public API reads do not cause artifact egress; auditing/readback and explicit source access do. Root should measure a bounded shadow/prospective workload before final sizing and capture the current owned-account prices, quotas, regions and recovery guarantees.

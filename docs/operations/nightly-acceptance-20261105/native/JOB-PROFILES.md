## Hosted admission

The four job steps invoke `native_jobs.py hosted-preflight` with their literal job IDs and the runner's actual `GITHUB_JOB`. Missing, substituted and relabelled local profiles fail. Intact local profiles also return a held status before dependency acquisition and DB steps. Writer checkout uses a nonpersistent repository token. Database and receipt-storage credentials are scoped to the consuming steps after admission. Provider dataset overrides reach the plan and consuming writer steps. The seed cache fingerprint and save require successful native admission, including on error paths. The workflow retains the source revision guard, trigger, job and step budgets, and refresh signature contract.

Activation requires all of the following.

1. An authorized existing distribution channel with read-only access to an immutable Linux amd64 manifest and its config and layers, exact source/archive provenance, retention and replacement/custody terms, measured capacity, and a cost disposition. The November 10 API read showed 1,127,690,464 bytes across five existing PDF caches under a 10 GB repository eviction ceiling and seven-day retention. It showed zero Actions artifacts with a 90-day default. Releases had zero assets and immutable releases were disabled. Package inventory and billing requests were refused. Repository-level cache arithmetic supplies no account-wide allowance or durable custody. [Actions cache behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching), [Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
2. An approved hosted launcher whose trusted host verifies job ID, exact source, manifest/config/rootfs and mount/network/resource policy before running the native image. Execute all writer work in that same verified environment and attest the fixed interpreter and full CPU/native inventory before permitting credentials. Keep the native worker separate from the Docker socket, and qualify its real runner shape with credentials absent and the same probe/corpus contracts. An image digest alone cannot freeze a runner's CPU. [Actions runner container mounts](https://github.com/actions/runner/blob/main/src/Runner.Worker/Container/ContainerInfo.cs).
3. An independent exact-version security disposition for the native dependencies and bundled Java libraries. Approve signed patched artifacts or enforce and verify bounded mitigation for applicable exposure. The local corpus envelope uses no network or writer credentials, a read-only rootfs and source, fixed scratch, one CPU, memory/PID/output limits and a wall deadline. A hosted writer with network access and database credentials needs an independently verified isolation boundary for untrusted document parsing.
4. Owner approval for the four hosted profiles and a reviewed activation change that connects the verified launcher to the existing admission and TLS steps. Retain the approval and exact qualification receipts with the applicable source and job evidence. The local bundle has no configuration switch that admits a hosted writer.

## Standard runner observation

Use the existing manual ingestion preflight on the execution draft with `purpose=native-runner-observation`. The job uses the same standard `ubuntu-latest` label as the four writer jobs. It records the actual CPU, verifies the pinned public base image, and exercises a read-only, unprivileged container with no network, mounts, or application credentials. The observation consumes runner logs and uses no artifact storage. Qualification of the complete native bundle and its hosted distribution remains a separate gate.

The OAG fallback uses a single-page Poppler command with a hard subprocess timeout, avoiding the unbounded metadata call inside the former conversion wrapper. It limits the raster accepted by OCR and selects the English Tesseract model with a timeout. Fiscal OCR also selects English explicitly. These controls address the reachable CPU loop and simultaneous-language paths. The fixed Poppler and Tesseract package versions or an approved parser isolation policy are still required for hosted writer admission.

### Credentialed parser boundary

The four GitHub writer jobs provision the reviewed wheel set and the sealed image before any database or receipt-storage secret is injected. Provisioning checks the repository, workflow, job, event and exact admitted SHA. The image is loaded from the existing immutable public release. A known PDF must exercise page counting and OCR, with a synthetic writer-only file outside the worker's mounts. The manual `isolated-parser-qualification` runs the same provisioner without production credentials.

Document parsing and retained replay for OAG, CoB, Treasury, KRA, county borrowing, CRA, census, workbooks and World Bank XML use a fresh container per operation. The container runs with its own network namespace, no host Docker socket, no inherited environment, a read-only root and only three read-only mounts: the reviewed source, the locked worker environment and the single request. The launcher checks the container setup before starting and removes it after each response or refusal. Source acquisition, reconciliation, source/edition checks and database writes remain in the trusted process. A response is bound to the input hash and restricted to a bounded data protocol. This boundary contains the parser; it cannot prove a syntactically valid extraction correct if the parser itself is compromised.

The OCR adapter now sends PDF page counting and one-page rendering to the locked PDFium child with an explicit environment and private working directory. The worker checks the physical page and raster dimensions before allocating the image. Tesseract uses a single language, a fixed invocation, and the same clean environment. The launcher bounds elapsed time and terminates the process group. The child bounds file size and, on Linux, address space. The writer checks stdout length before consuming it. The OAG catalogue XML parser rejects document type declarations at the parser callback, including UTF-16 input.

The application OCR path no longer reaches Poppler's Splash renderer or the system OpenJPEG JPEG 2000 decoder. Poppler 26.11.0 still carries the positive-repeat path in [CVE-2026-93653](https://security-tracker.debian.org/tracker/CVE-2026-93653). The image's linked OpenJPEG 2.5.3-2.1~deb13u2 is affected by [the SOD bounds advisory](https://security-tracker.debian.org/tracker/TEMP-1153269-522F63). The [locked PDFium build](https://pdfium.googlesource.com/pdfium/+/refs/heads/chromium/8076/third_party/libopenjpeg/README.pdfium) includes the upstream SOD bounds check. The sealed image still contains Poppler for its offline corpus checks; the approved application OCR commands use PDFium and Tesseract instead.

Tabula Java and C-only Git serve owned fixtures in the native qualification. Legacy ETL has separate Tabula call sites on downloaded documents. [PDFBox's example-class advisories](https://pdfbox.apache.org/security.html) affect classes absent from the locked jar. Its transitive parser dependencies still require review for any untrusted legacy input. The native seeder does not call Perl. Java, Tabula and Perl are outside the approved nightly parser operations; they remain in the qualification image for the fixture suite. The image is never given writer credentials. A smaller parser-only image remains useful for reducing the container's attack surface. The [Git recursive-clone advisory](https://github.com/git/git/security/advisories/GHSA-vp2w-7xxj-jvxr) does not reach the candidate's local fixture operations.

Before changing the production ingestion pin, complete the hosted qualification on the exact combined source and check the production schema. Keep the four unrelated controls off. A clean manual qualification verifies the runner and isolation, while a subsequent scheduled seed and refresh provides the separate end-to-end production receipt.

Asset: id, version, filename, state, nullable mime_type/byte_size/sha256/width/height/duration_ms, default_alt_text, safe_error, created_at. Pending metadata remains NULL. Library includes ready assets across admins. URLs/storage keys/tokens never enter asset summaries or post documents. Upload/version/key replay is durable; changed commands conflict. No PostDocument/MediaReference/resolved payload schema changes.

Both browser upload and completion retries retain the original command. A lost accepted PUT followed by create-only412 proceeds to authoritative completion/inspection, which alone admits readiness. A storage finalize whose completion cannot be confirmed produces MEDIA_FINALIZATION_UNKNOWN after its active lease expires, retains quota, and requires operational reconciliation; it is never retried as if remote creation had definitely stopped.

## Storage, inspection and operational gates

Unavailable by default. Explicit environment names: SOCIAL_MEDIA_ENABLED true/false, SOCIAL_MEDIA_R2_ENDPOINT exact account HTTPS S3 endpoint, SOCIAL_MEDIA_BUCKET, SOCIAL_MEDIA_ACCESS_KEY, SOCIAL_MEDIA_SECRET_KEY, SOCIAL_MEDIA_FFPROBE_PATH absolute executable. Invalid config/missing SDK/inspectors never substitute fake storage. Credentials/grants do not appear in storage reprs or audit/log fields. No .env, bucket, billing, security setting, deployment, provider credential or production migration changes.

One optional private R2 backend. Browser sends File bytes directly to a quarantine key using a short signed PUT with exact Content-Length/Content-Type/If-None-Match. Authenticated Axios handles only metadata; isolated fetch omits cookies/JWT and rejects redirects. R2 supports signed PUT rather than form POST; signed grants are reusable bearer credentials until expiry. [R2 presigned URL documentation](https://developers.cloudflare.com/r2/api/s3/presigned-urls/) and [S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/).

The SDK uses total_max_attempts=1 (one total wire attempt). A timed-out PUT is never settled by HEAD; only normal single-attempt HTTP200 or confirmed HTTP412 with zero SDK retries can advance to byte verification. The actual installed botocore transport was exercised with a fake ReadTimeout: old max_attempts=1 made two wire attempts (red), total_max_attempts=1 makes one (green). [Boto3 retry configuration](https://docs.aws.amazon.com/boto3/latest/guide/retries.html).

Completion releases SQL locks before all object I/O. It streams bounded original bytes into a private temp file; local tools inspect actual MIME, dimensions, length, SHA256, timing/codec/sample evidence. Final storage key is separate/create-only; final bytes are re-read and hashed, including confirmed precondition-rejected create recovery. Ready storage identity/checksum is immutable and preview HEAD verifies saved ETag/version/size/MIME/hash before a short storage-only GET grant. No arbitrary URL downloads, rendering, transcoding or generated derivatives.

Initial intake is static JPEG/PNG10MiB, or progressive MP4 with H.264 and optional AAC50MiB/120s. Images must decode fully and fit16million pixels. Video requires positive complete declared/read samples and decoded frames, finite timing, one H.264 stream, optional AAC, no ffprobe errors; fragmented/unsupported structures fail. [ffprobe count_frames/count_packets documentation](https://ffmpeg.org/ffprobe.html). Child replaces itself with ffprobe so parent timeout kills the decoder itself. CPU15s/output64KiB/file descriptors64, Linux address space512MiB, max allocation64MiB, single decode thread, external MOV references disabled, file-only protocols, parent timeout20s. No large-memory/video response body in API. Resource limits can reject otherwise valid costly videos; verify representative uploads before enablement.

Before enabling, verify actual R2 create-only/length/CORS behavior, restricted private credentials, expected short grants and synchronized clocks, disabled public/custom-domain storage, Pillow/ffprobe patched maintained builds, temp disk and bounded worker capacity. Inventory any existing bucket assets and reconcile reservations before enabling; the new quota ledger cannot account for unmanaged legacy objects automatically. ## Accounting, cleanup and retention

Initiation reserves **two times declared bytes**, covering simultaneous quarantine+final originals. Global physical reservation defaults2GiB, per-admin200MiB, three pending uploads. Confirmed ready quarantine cleanup releases one copy; confirmed orphan cleanup releases the remainder exactly once. All mutation locks follow global→actor→asset. Candidate eligibility is filtered before LIMIT and rechecked under locks; failed deletes retain reservation and retry after lease expiry.

Call MediaService.cleanup(limit<=20) from a separately provisioned scheduler with a fresh short-lived session. It removes expired incomplete/failed orphan bytes and ready quarantine copies. It preserves ready originals, audit rows and currently referenced nonready assets. Unknown finalizations retain both reservation and pending capacity; late known completion records its epoch settled even if the DB lease was lost, then permits fenced orphan cleanup. **Do not force-clear unresolved markers or release their quota just because a lease expired.** An operational reconciliation/lifecycle workflow must establish the remote outcome before clearing an unknown epoch; automated unknown reconciliation is intentionally not shipped. This may require manual service restoration before additional uploads, while storage remains bounded.

Ready originals are retained even when currently unreferenced. Automatic ready retention/deletion requires a shared reference/deletion lock in domain saves and is disabled. Current nonready-reference checks retain existing references, but a concurrent direct domain save can still add an unusable nonready reference after cleanup's check because parent domain does not share the media lock; publish validation rejects nonready assets. Parent should add the common lock/state check before extending retention or guaranteeing all reference/delete races. Approved/ready evidence is never deleted by this feature.

# Review extension: assigned PostgreSQL fixture safety

The genuine #487 comment at discussion_r4175471207 identified libpq query overrides in the new egress harness. Parent audit found the same authority-only validation in four inherited social fixtures: domain/migration, durable worker, API/worker integration and Meta connection locking. Media cleanup has the same pattern and is aligned in #492. This is an understated finding; production worker configuration is not restricted to loopback.

The shared test-only `local_postgres_url` rejects caller query syntax before parsing (SQLAlchemy silently drops blank query values), unassigned database names, wrong ports, non-loopback authorities and non-synchronous drivers. It returns an explicit psycopg2 URL with both `host` and `hostaddr` pinned to 127.0.0.1. Environment defaults therefore cannot redirect an otherwise accepted fixture. The generated pinned query is only used after validation. Percent-encoded question marks in passwords remain valid. Missing opt-in DSNs continue to skip.

Executed receipts on the pre-fix fixture entry points: **32 assertions failed**. Twenty-eight hostile query cases reached intercepted engine creation; four valid-looking localhost cases lacked the explicit host-address pin. These tests never created an engine or connected remotely. A second probe after the initial implementation failed for blank `?host=`, confirming parser omission; the raw-syntax guard corrected it.

The initial guard integration passed **70 target-safety tests** and **336 combined backend social tests in 20.27 seconds**, using the explicitly assigned disposable PostgreSQL databases on port 62124. Independent verification then found the actual crash-test child still consumed the raw environment DSN. A new child-configuration regression failed before the fix; its copied environment now uses the validated parent engine URL, without changing the parent environment. Final focused verification passed **71 shipped guard tests**, **121 independent adversarial assertions**, and the **actual process-kill/recovery test under hostile `PGHOSTADDR`**, with one fake remote receipt and no republishing. The full-suite baseline includes real DDL/RLS/foreign-key, worker crash/retry and credential locking tests. Two existing SQLAlchemy deprecation warnings remain. No production query, schema, role, configuration, installed package or existing worker process changed.

Reproduction uses the existing backend interpreter, `PYTHONPATH=backend`, `PYTHON_DOTENV_DISABLED=1`, and explicit local test variables: `SOCIAL_TEST_DATABASE_URL` for `social_domain_test`, `SOCIAL_WORKER_TEST_DATABASE_URL` and `SOCIAL_CONNECTIONS_TEST_DATABASE_URL` for `social_worker_test`, and `SOCIAL_INTEGRATION_DATABASE_URL` for `auditgava_social_test`. Run `python -m pytest backend/tests/social -q --tb=short`; never substitute a deployed DSN.

## Admission and operation

`python -m social_metrics TARGET_UUID --authorization /owned/command.json --enable-native-collection` (from backend). Exact command binds account UUID, platform credential UUID/version, published payload hash, remote ID and runtime source/config hash. Meta retains exact parent UUID/version; Threads/TikTok omit both. Native read credentials use the existing encrypted `platform:{platform}:credential` namespace, exact subject/open_id/scopes and expiry, with no outstanding refresh claim/revocation. Account/product/connection/format/current public target are revalidated before reservation and after response. No connection or credential is created by metrics collection.

`SOCIAL_ANALYTICS_ENABLED=true`, existing operational/free verification settings, platform list, generation and stable existing cipher configuration are required. **Additionally** Threads/TikTok account UUIDs must be explicitly listed in `SOCIAL_ANALYTICS_NATIVE_ACCOUNT_IDS` (up to50). This means access/product/own-account/Analytics opt-in and free access were accepted separately for those exact accounts. Leaving it absent refuses native capability. No Meta app secret is required for a platform-only runtime. Mixed Meta runtime still requires its app secret.

Optional `SOCIAL_PLATFORM_POLICY.threads.threads_insights_enabled=true` allows a **future human-authorized OAuth flow** to request `threads_manage_insights` in addition to existing scopes. Default false; existing grants do not gain permission. TikTok's existing explicit console-approved policy `scopes` must include `video.list`; posting-only grants are insufficient. No runtime configuration or grant was changed in this batch.

One durable quota reservation precedes one request, with source/config/command/request provenance in immutable audit history. No retries, pagination continuation, profile discovery, status reconciliation or hidden read occurs. HTTP and owned spawned-process deadline10s; body cap32768bytes; at most20 normalized records. Existing transports enforce no redirects, duplicate JSON/nonfinite/body/compression refusal. Raw provider responses and credentials are not stored. Failure consumes quota; interrupted new native reservations stay held without age-based replay. Rate limits produce unavailable observations with safe Retry-After timing stored on the collection; account-wide later commands respect the server's longer delay across restarts. Missing/invalid Retry-After holds collection pending review. No force-clear command is provided.

Observation value0 is available only if supplied as an actual integer zero. Missing/null remains unavailable. Provider window boundaries remain null when not supplied; collection time/freshness is not a claim of real-time TikTok data. Counts are namespaced by target platform and exact API version in existing API/UI. Durable observation/audit readback refuses suppressed/altered required writes before dispatch/success. Existing PG history guards protect append-only observations; no migration or role/grant change is required. Existing admin-only no-store APIs display the results with unavailable/freshness/window distinctions.

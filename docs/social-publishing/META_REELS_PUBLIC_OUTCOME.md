# Meta Reels record-existing authority — 18 October 2026

META-REEL-PUBLIC-001 implements the original Blueprint§17.2/18 audited record-existing authority for Facebook Page Reels (`facebook_pages`) and Instagram Reels using Facebook Login (`instagram_graph_facebook_login`). The transport's authenticated status or own-media read remains Processing/unknown; this procedure provides independently audited **human authority**, not automatic provider proof. It uses existing admin authorization, audit/receipt tables and existing operator evidence custody. No new account, role/grant, flag, paid service, storage resource or provider request is introduced.

Two different authenticated administrators must independently examine the exact complete Reel in a browser without Meta login, cookies or sessions. Each must separately retain (1) an anonymous public capture packet showing the whole caption and complete video/audio and (2) an owner/identity capture packet binding the numeric platform owner and final numeric media/video ID to that exact canonical Reel URL and product. Authenticated API/owner readback may supply identity evidence only. A URL, logged-in view, checkbox, matching caption, provider success boolean or arbitrary hash alone does not establish public availability.

Each administrator independently compares the full rendered original MP4 at its approved SHA256 against the complete public video/audio, including all scenes/captions and any audio. Providers may transcode; the public video is **not** asserted byte-identical to the uploaded original. The approved original hash binds source custody and review, while full-content comparison is accountable human observation. If complete video/identity/caption/public availability cannot be checked, refuse. Private, age/country restricted, login-walled, unavailable or partial views do not qualify. A limited region's visibility must not be represented as unrestricted public visibility. Automated resolution cannot copy the server context into an observation.

Retain four independent packets (two per administrator) using UUID custody references resolvable in existing approved operator custody, their SHA256, timestamps and the comparison/identity bases. Retain bytes for the publication evidence retention period; no packets/credentials need uploading through this API. The second administrator must inspect the first pair and independently create its own pair. Both the operator procedure and independent captures are authority assumptions; the server validates shape/binding/independence but cannot verify off-system pixels or the truth of two administrators. No cryptographic provider signature is claimed. Collusion or false attestation by two authorized administrators lies outside this trust model; assigning actual operator authority/custody remains separate acceptance.

## Scoped API

Existing admin-only routes under `/api/v1/admin/social/targets/{target_id}/meta-reels`:

- `GET /public-proof`: exact immutable revision/approved hash, payload hash, selected account/product, composed caption, original asset SHA256, known final remote ID, publication version and operational binding hash. This is comparison context, not evidence.
- `POST /public-proof`: `{expected_publication_version,binding_hash,observation,reason}` creates an append-only proposal, with no delivery state change.
- `POST /record-existing`: `{expected_publication_version,proof_id,observation,reason}` from a **different admin** independently admits the same Reel and records `published/public` with confirmation `meta-reels-two-admin-public-v1`.

Every POST requires a UUID Idempotency-Key. Same actor/route/key and identical body returns the original durable result, even after response loss; a different body conflicts. Keep the original key while an HTTP outcome is ambiguous. There is no resend operation.

Observation fields: exact `platform`, `method=anonymous_browser`, `visibility=public`, fresh aware `observed_at`, public `capture_sha256`/`custody_reference`, separate `identity_capture_sha256`/`identity_custody_reference`, exact numeric `external_account_id`/final `remote_id`, canonical `remote_url`, full composed `text`, approved original `asset_sha256`, and30–1000-character `identity_basis`/`media_comparison` descriptions. Facebook URL must identify `/reel/{numeric video_id}`; Instagram URL must identify `/reel/{shortcode}/`. A container ID is never a published Instagram media ID. New observations cannot replace contradictory retained final identities. All capture hashes/references must be separate and unused, including opposite public/identity packet roles.

Both captures must be no more than thirty minutes old and not in the future, using database time. Proposal expires thirty minutes after its first observation, without extension by late submission. Proposal binding includes current publication version, target state/checkpoint/refs/lease epoch/count/update time and original dispatch operation. Worker progress or approval/source/product changes require fresh evidence. Only unresolved attempted Reels with a durable public dispatch permit qualify. Any target/account lease, expired-but-retained ownership, or unfinished attempt refuses. Complete ordinary worker recovery first.

Transactions lock existing controls, account, publication and target in worker-compatible order. The exact approved revision/payload/selected media/product and retained original ready asset must match. Duplicate final remote identity is checked across accounts/products with the same numeric provider owner, and all evidence is retained. Audit, exact target settlement, publication version, target-specific account-hold release and idempotent receipt commit together, with stored-row and deferred-trigger verification. Sibling targets, attempts, checkpoints, other holds, cancellation and credential/control state are preserved. A pause/cancellation/deadline does not erase a past public outcome and cannot authorize another send.

The completed human recovery authority may advertise Reels delivery **with operator confirmation required**; automatic public confirmation and unattended completion remain unsupported. Account-specific native admission and all ordinary dispatch/approval/source/custody controls remain mandatory. Live publishing/uploads/supervision remain off unless separately authorized and accepted. Positive local fixtures exercise this human trust contract, not real provider/public proof or operational custody acceptance.

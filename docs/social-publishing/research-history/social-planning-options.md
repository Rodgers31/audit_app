# AuditGava social publishing options — October 3, 2026

Read-only official documentation and SDK source review. No accounts connected, purchases made, live API publishing attempted, application files edited, or existing processes/branches changed. Provider declarations below are documented support, not a live-verified AuditGava grant.

## Plain recommendation

Build AuditGava's review, approval, evidence and delivery ledger in its own FastAPI/Postgres backend. Put delivery behind a replaceable interface. For the fastest first integration, evaluate **a managed API directly from Python**, particularly Zernio and Post for Me, before deciding whether the additional Social SDK layer is useful. This removes much of the OAuth/app-maintenance work and avoids requiring a Node service merely to wrap an HTTP API. It does not remove the need for AuditGava's own durable approval and safety controls. Use native Meta APIs plus selected SDK adapters if control over credentials and platform-specific features is worth the extra maintenance.

**Social SDK is useful but is not the complete system, and is not demonstrably the best single option.** Main and npm remain at the prior audited snapshot: main commit `a76fb612c8abd5926fbfa40c9a3f556a523531ea` dated September 29; npm latest `0.5.0`, Node >=22.12. Postiz is present on main but absent from the published 0.5.0 export set. SDK source offers no direct Facebook adapter. [Pinned manifest](https://github.com/opencoredev/social-sdk/blob/a76fb612c8abd5926fbfa40c9a3f556a523531ea/packages/social-sdk/package.json), [npm metadata](https://registry.npmjs.org/@opencoredev/social-sdk/latest).

## Important correction to the earlier TikTok conclusion

There are **two distinct TikTok publishing routes**, and a restriction on one should not be generalized to both:

1. **TikTok for Developers Content Posting/Direct Post:** official guidelines reject utilities uploading only to accounts the developer or its team manages, require a broad-audience app, public Direct Post audit, creator preview, current privacy choices and express consent. AuditGava-only admin appears to conflict with this intended use; that is an inference, not an actual application rejection. SDK consent flags do not manufacture consent. [TikTok Content Sharing Guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines).
2. **TikTok API for Business → Organic Accounts API:** official permitted uses explicitly include managing brands'/creators' owned accounts, video/photo publishing, comments and insights. A developer may be the business itself. New app/scope requests for TikTok Accounts require an access application, effective March 20, 2026. This is a plausible and more appropriate route to investigate for AuditGava. It is not proof that AuditGava has access or that every future unattended workflow is approved. [Official Accounts API overview](https://business-api.tiktok.com/portal/docs/accounts-api-overview/v1.3).

Zernio says new TikTok connections now use its Business app route, supports photos/video/scheduling and creator-inbox drafts, and still requires preview confirmation and express consent per post. Post for Me separately exposes `tiktok` and `tiktok_business` connections; both can connect personal or business accounts, while Business supplies richer analytics and custom thumbnails. A Business API connection is distinct from merely converting the consumer profile to a Business account. [Zernio TikTok guide](https://docs.zernio.com/platforms/tiktok), [Post for Me's two-route guide](https://www.postforme.dev/resources/tiktok-vs-tiktok-business-api).

Therefore: **TikTok publishing is not categorically impossible. Investigate and validate the Business/Organic route first; retain manual export/native upload until it is confirmed. Do not promise unattended TikTok publishing yet.** A provider using an approved app may offer a legitimately different authorized route; that is different from bypassing the standard Direct Post restrictions.

## Verified advertised cost snapshot

- **Zernio:** first two connected accounts free; accounts 3–10 cost $6 each/month. Five connected posting accounts calculate to **$18/month**, before X API usage and other metered features. X charges are passed through; a URL-containing create request is advertised at $0.20 versus $0.015 for basic creation. Recheck quote before purchasing. [Zernio pricing](https://docs.zernio.com/pricing).
- **Post for Me:** pricing page shows **$10/month for up to 1,000 successful posts**, unlimited accounts/projects/team members; use provider credentials or own credentials. Confirm per-destination counting and X-specific charges contractually. [Pricing](https://www.postforme.dev/pricing).
- **Postiz Cloud:** Standard **$29/month, five channels**, API/webhooks included; Team $39/month adds ten channels and unlimited team members. Self-hosted source is a different cost equation because hosting/maintenance/provider apps remain ours. [Postiz pricing](https://postiz.com/pricing).

No provider is selected or purchased by this research. Cost alone should not decide reliability, policy fit or handling of unknown publish outcomes.

## Technical details that affect selection

**Zernio TikTok contract drift:** current docs require a top-level `tiktokSettings` object, accepting snake_case/camelCase fields. SDK pinned `cloud/zernio.ts` instead sends the TikTok fields inside a destination's `platformSpecificData`. This is a documented-shape mismatch, **not a demonstrated live failure**. Validate the exact current request before adopting the adapter; using the provider API directly avoids relying on this unverified mapping. [Current guide](https://docs.zernio.com/platforms/tiktok), [SDK source around request mapping](https://github.com/opencoredev/social-sdk/blob/a76fb612c8abd5926fbfa40c9a3f556a523531ea/packages/social-sdk/src/cloud/zernio.ts#L410).

**SDK routes do not uniformly expose new Business features:** Post for Me's SDK connection helper validates its platform enum through the common selection list, which has `tiktok` but not `tiktok_business`. Main's Postiz adapter recognizes `tiktok-business` as TikTok, but uses generic TikTok settings. Therefore provider business capabilities should not be assumed available through every normalized SDK route. [Post for Me SDK connection helper](https://github.com/opencoredev/social-sdk/blob/a76fb612c8abd5926fbfa40c9a3f556a523531ea/packages/social-sdk/src/cloud/post-for-me.ts#L525), [common platform list](https://github.com/opencoredev/social-sdk/blob/a76fb612c8abd5926fbfa40c9a3f556a523531ea/packages/social-sdk/src/cloud/common.ts#L40), [Postiz mapping](https://github.com/opencoredev/social-sdk/blob/a76fb612c8abd5926fbfa40c9a3f556a523531ea/packages/social-sdk/src/cloud/postiz.ts#L110).

**Notifications:** Zernio signs raw-body webhooks with HMAC-SHA256, supplies stable event IDs and retries up to seven attempts; durable dedup and asynchronous processing remain ours. Post for Me supplies a shared-secret header, expects acknowledgment within one second and retries approximately eight times in 24 hours; verify results via provider API where needed. [Zernio webhooks](https://docs.zernio.com/webhooks), [Post for Me webhooks](https://www.postforme.dev/resources/real-time-updates-with-webhooks).

**Postiz is active but not a drop-in compliance workflow:** official latest release v2.25.0 is October 2; v2.24.0 introduced a separate TikTok for Business provider. Its approval documentation explicitly states there is no approved flag blocking publishing, and preview links are unprotected/unlisted. API create-post supports `draft`, `schedule`, `now`; create-post rate budget is 90/hour self-hosted or 100/hour Cloud. AuditGava should keep sensitive drafts private and its own revision-bound approval gate regardless of Postiz. [v2.24.0](https://github.com/gitroomhq/postiz-app/releases/tag/v2.24.0), [v2.25.0](https://github.com/gitroomhq/postiz-app/releases/tag/v2.25.0), [Approval limits](https://docs.postiz.com/general/approvals), [API overview](https://docs.postiz.com/public-api/introduction).

## Before selecting delivery

Run a later authorized, controlled compatibility proof: connect the actual Page/professional Instagram/Threads/X accounts and the selected TikTok Business route; publish one reviewed original item per permitted format; confirm remote URLs, delayed processing, denied scopes, token reconnect, webhook authenticity, duplicate prevention, uncertain acceptance and per-platform retry. Ask the TikTok provider for the exact permitted AuditGava internal-team workflow, approval/scheduling consent retention, and whether selective unattended publishing is permitted. This is the unresolved eligibility question, rather than whether a checkbox can be set in code.

Regardless of vendor, AuditGava must own source verification, immutable revisions, approval, post limits, emergency pause, per-platform receipts, and correction policy. A pause can stop future dispatch but cannot reliably retract material already accepted by a provider/platform. An API "delete" of a queued database record must not be presented as deletion of a published social post.

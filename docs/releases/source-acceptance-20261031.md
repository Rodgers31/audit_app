## OAG producer, reader and editorial behavior

The native audit producer acquires one bounded RSS receipt per independently read fiscal edition, caching a failed attempt as well as a successful one. The cap is 512 KiB and 20 seconds per edition, not one request per document or county. An unavailable feed records a refusal; a captured feed is not automatically accepted.

The closed contract requires the exact official feed identity, one scalar full RFC entry timestamp with explicit timezone and valid weekday, exact PDF link, document-entry GUID, reviewed complete title spelling, and a separate complete physical PDF title page. Conflicting kind, fiscal year, volume, subperiod, duplicate fields, ambiguous namespaces, wrong links or serialized runtime capabilities refuse. Review found a punctuation edge case in conflicting cover labels; the unchanged desired failing fixtures pass after the repair.

Only the two explicit KRA/OAG catalogue contracts are dispatched by the shared writer/reader. Publication and catalogue evidence cannot silently substitute for each other. Cached OAG PDFs reuse the immutable original acquisition only after current job-bound retained-byte validation, with a fresh paired RSS receipt. Missing, changed or stale original evidence remains a refusal. The current-reader and restricted digest witness recheck the selected institution/edition and all nested metadata. No schema, authority-view definition, role or production grant changes are required.

The caption states the exact institution and fiscal year, the catalogue entry date, and that the report's publication date is not stated and human review is required. Its canonical destination is AuditGava's `/audits` route. The typed OAG catalogue record cannot become financial evidence, and the existing `CATALOGUE_HUMAN_REVIEW_REQUIRED` automation guard applies.

## Memory defects and repair

The complete national PDF killed the old fresh parser at its existing 512 MiB cap: exit137, `OOMKilled=true`, 113 completed pages. Layout caches remained resident between pages. Every page now closes in `finally`, retaining its extracted text and page order and propagating extraction errors. The actual repaired producer accepts all twenty cells within 512 MiB; completed baseline text hashes, all 46 retained reference page texts and financial values remain equal. The old text fixture's PDF MD5 differs from the fresh genuine PDF and is treated only as a text/value reference, never a same-body acquisition receipt.

OAG's genuine FY2023/24 executive cover independently killed the old single-document capture at 512 MiB during page-one text extraction. Releasing previous pages alone did not fix it. Cover artwork caused large vector/image layout allocations. The final cover reader uses the same pdfplumber glyph, font, text and marked-content interpreter, discarding only vector/image layout objects that never supplied `extract_text` characters. It reads at most three physical pages, closes each layout and its owned stream, and avoids pdfplumber's whole-document `PDF.pages` traversal, including the implicit repeat during `PDF.close`. It never skips page one, substitutes OCR, changes text engines or drops a conflicting text qualifier.

The external prototype's executive cover text is byte-identical on all three pages at a 276,492,288-byte cgroup peak. Separate final-function captures preserve every reference cover text for the four accepted and two refused OAG inputs plus the national cover; the independent maximum final capture peak is 271,990,784 bytes. Prototype results are not relabelled as final-function results. The genuine two-volume producer→PostgreSQL→preview, retained replay and restricted-login witness cases pass three cases in each mode at 512 MiB. Earlier OOM and larger local-fixture runs remain in the evidence ledger without resource acceptance credit.

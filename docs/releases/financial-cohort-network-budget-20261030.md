## Measured cause and repair

Two independent owned PostgreSQL rehearsals reproduce the deployed deadline failure with 130 ms added per driver execution; one reproduces the exact 23/20/3 partial result. This is a disclosed latency simulation, not a directly measured GitHub-to-database RTT. A bounded read-only production row profile from Render qualifies the actual source with modest metadata sizes (source 1,908 bytes; qualification receipt 24,684 bytes). Repeated round trips, rather than very large source JSON, are the supported bottleneck hypothesis.

The deployed retained baseline path executes 1,784 SQL calls for 46 rows. This change combines each job/timestamp/newer-head check into one current statement, combines the existing inherited lock-timeout bound and transaction mutex through a materialized dependency, and omits conflict inserts when controls or the source marker already exist. Missing initialization still inserts and rereads under the existing uniqueness/locking discipline. No admission result is reused across row transactions; current source/measure/chronology/retained-origin/quarantine checks and exact final completion attestation remain.

Independent query-only profiles reduce the retained baseline to 1,364 calls, unchanged refresh to 1,315, and a full 46-row meaningful-change cohort with installed worker authority and an inert Facebook editorial account to 2,880. All changes create held review drafts, with no publication or dispatch targets. Counts exclude connection/commit protocol and are fixture-specific.

At a conservative simulated 150 ms, 2,880 driver calls account for 432 seconds before connection, commit, CPU and receipt overhead. The pending-bills financial phase therefore has a finite 600-second cap; the report phase stays 30 seconds and receipt reserve stays 10. Other domains retain their existing phase limits. The CLI clamps the hook envelope to the remaining original whole-run deadline and reserves cleanup there. An exhausted run records a known zero/not-started result rather than entering the zero-second alarm path. Confirmed financial results survive a later report timeout. The 2,400-second overall run, 600-second source cap, 45-minute seed step and 50-minute job limits are unchanged.

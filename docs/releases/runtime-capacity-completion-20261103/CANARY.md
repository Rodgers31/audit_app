## Separate active acceptance

An idle pass cannot qualify a media/provider workload. Later acceptance requires
authorized real browser intake/inspection/private-preview/attach; retained-media
custody and independent nonempty restore; restricted-role native queue processing,
provider reconciliation and ambiguous outcome recovery; combined web+worker
memory/CPU/PID/connection/API latency under intended overlap; sustained SQL and
protocol bytes, service-class egress and a representative closed operating day.
One tiny codec, an emulated fixture or a180s idle sample supplies none of those
results. Existing shutdown/logical-restore proofs remain accepted only in their
actual prior scope. No free-tier or guaranteed no-new-egress-cost claim is made.
